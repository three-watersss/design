# 拾光 · 本地素材工作台

将选题表变成可审核的图片与文案，并管理未发布素材。使用已登录的 Codex CLI / ChatGPT 订阅，不使用 OpenAI API Key。

## 启动

在 Mac 上双击 **启动素材工作台.command**。首次运行会安装项目依赖、编译界面、启动本地服务并打开浏览器。再次双击会打开已经运行的实例，不会重复启动队列。

前置条件：Node.js 24 或更新版本、npm、Codex CLI，以及可用的本地代理。如尚未安装 Codex CLI，在终端执行 `npm install -g @openai/codex`，然后执行 `codex login`，选择 ChatGPT 登录。界面右上角可查看登录与代理检查结果。

默认入口：<http://127.0.0.1:4317>。服务仅绑定本机地址。关闭网页不停止生成；重新打开网页可继续审核。双击 **停止素材工作台.command** 可停止服务及其生成子进程；未完成阶段下次启动恢复。

## 使用

1. 点击「导入选题」，上传 XLSX。第一张工作表须有「账号名」「主题」表头；空值会标出，重复选题默认跳过，可勾选保留重复。
2. 等待生成后检查整组图片，选择「通过，生成文案」或「重新生成」。
3. 检查文案，选择「通过，保存素材」或「重新生成」。
4. 素材库只展示人工审核通过的完整素材。
5. 发布台可按账号挑选未发布素材。复制文案、下载图片后自行在小红书发布；本工具的「发布」按钮仅记录状态，不向小红书上传。

发布台选中素材后，点击「图片组」右侧的文件夹图标，即可在 Finder 中打开这一组原图所在目录，方便整理发布内容。

素材库只展示图片、文案均审核通过的完整素材。在「未发布」页，每个素材卡片左下角有删除图标；确认后永久删除整组素材、SQLite 关联记录和本地执行文件。删除中断会在重启或恢复队列时继续清理。已发布页不提供删除入口。

重新生成直接删除当前阶段的旧结果，不保留历史对比。文案重生成保留已通过的图片。换一组不会改变发布状态，同一轮不会重复展示已看过的素材。

## 可编辑文件

- `prompts/images.md`：图片提示词，来自原 DOCX，保留原有重复段落；支持 `{{account}}` 和 `{{topic}}`。
- `prompts/copy.md`：文案提示词，支持相同占位符；模型会额外收到真实生成图片。
- `config.toml`：模型、思考程度、并发、代理、执行超时、端口及数据目录。修改后停止并重新启动工具。

每次新生成与人工重新生成读取最新提示词文件；已开始的执行固定使用其快照。自动中断恢复和退避重试沿用该次执行原快照。提示词本身修改后不用重启。

文案只检查 `title`、`body` 的结构、字符串类型和非空内容，不限制标题或正文的字符数量；长度要求由 `prompts/copy.md` 决定。界面字符统计仅供参考。

默认 GPT-5.6 Sol / high、总并发 3、30 分钟超时、HTTP 代理 127.0.0.1:7897。图片张数由 `prompts/images.md` 决定；程序不再限定六张或任何固定张数，只拒绝空图片结果。旧配置中的 `image_count` 不再使用；原提示词中的张数要求仍按原文保留，由你自行编辑。文案阶段会附带实际生成的全部图片。完整校验清单见 [生成结果检查](docs/生成结果检查.md)。

图像实际由 Codex 内置图像工具生成，主模型设置不等同于图像引擎型号。图片尺寸偏差只提示，保留原图，不做后期缩放。

## 恢复与限流

SQLite 持久化任务状态，文件保存到独立执行目录。图片生成中断时删除整组半成品再生成；已完整落盘且执行成功的结果直接回到审核阶段。文案中断不会重做已通过的图片。审核等待、完整素材及发布标记在重启后保留。

后台以单实例锁和执行编号避免重复派发。独立监督进程会在服务退出、超时或被替换时停止 CLI 进程组；恢复前确认旧进程已结束。清理采用持久化状态，可在清理中断后继续执行。

全局限制最多 3 个阶段并发，人工审核不占名额。此值仅约束本工具，不保证 Plus/Pro 账号整体不会限流，其他 Codex 使用也会占用账号容量。明确限流时全局暂停派发，前两次失败分别退避 60、120 秒；连续第三次失败停止该阶段自动重试，并冷却队列 240 秒。额度不足、登录失效或代理错误会阻塞队列；处理后点击「恢复队列」。其他异常显示在选题详情中，不无限重试。

## 数据与诊断

`data/materials.sqlite` 是正式数据库，`data/attempts` 保存当前图片、文案结果及必要执行文件。数据库、数据目录、缓存和旧验证记录不进入版本管理。备份时先停止服务，再完整备份 `data`（以及修改过的配置和提示词）。不要只备份 SQLite 而漏掉图片。

放弃结果时删除应用文件及可归属本次 CLI 会话的 `generated_images/<thread-id>` 缓存。CLI 使用临时会话；应用不保存完整 JSONL 文案日志，不清理其他 Codex 任务。旧 `validation` 目录是前期验证记录，不会自动进入正式素材库。

启动器错误显示在终端；后台启动诊断在 `startup.log`。界面提供环境检查和可操作的异常提示。运行配置不包含 API Key，调用时显式排除 API Key 环境变量。

## 开发与检查

```sh
npm ci
npm run build
npm test
npm start
```

生产构建由本地后端同时提供前端与 API；实时状态通过 SSE 推送。服务端使用 Node 内置 SQLite，避免原生数据库模块编译。接口仅接受本机 Host 和同源页面请求。

目前验收重点是图片、文案、审核、删除、恢复和发布状态；不包括跨机器同步、多人协作、自动发布到小红书、后台自动挑选成品、历史版本对比。

构建、自动化测试与真实调用的结果见 [验收记录](docs/验收记录.md)。真实生成结果须在工作台手动审核，隔离测试不会替你通过或发布正式素材。
