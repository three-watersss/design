# 当前生成结果的程序化检查

更新日期：2026-09-25。对应 `server/runner.ts` 和 `server/service.ts`。

## 两个阶段共有

- CLI 必须结束，监督进程的执行回执必须存在且可解析，退出码为 0；启动失败、超时、异常退出不当作成功。
- 执行目录必须存在可读取、可解析的 `result.json`，根节点必须是对象。
- 提交状态前核对任务仍在生成中、执行编号仍匹配；旧执行迟到结果不会覆盖新任务。
- 通过校验后仅进入待审核，仍需人工通过，才能推进下一阶段或成为完整素材。

## 图片：不通过就不能进入审核

1. `images` 是非空数组。已删除固定张数、最低六张、最高六张限制；1、3、8 张等均可。程序也不会推断提示词要求的张数来重新设限。空数组表示没有生成任何图片，仍拒绝。
2. 每项是字符串路径；文件必须存在，解析后的路径及真实路径都必须在本次执行的 `images/` 目录内，不能通过 `..` 或符号链接指向目录外。
3. 同一文件路径不能重复；文件内容的 SHA-256 不能重复，即不能用相同文件凑一组。不会检查两张图片在视觉上是否相似。
4. 图片必须能被 Sharp 读取元信息并实际解码，有有效宽、高，格式仅允许 PNG、JPEG、WebP。
5. 元信息读取设置 100,000,000 像素上限（单张一亿像素）。此上限用于防止异常大文件耗尽内存。

张数由提示词决定；文案阶段使用实际图片清单，而不是固定附加六张。

## 图片：仅提示，不拦截

仍保留旧模板的参考尺寸：第一张 1242×1656，后续图片严格按宽×9＝高×16 判断 16:9。只要存在偏差就提示，保留原图，不缩放、不裁切、不因此重试。该参考值目前写在程序中，不会自动从新提示词提取。

## 文案：不通过就不能进入审核

- Codex CLI 的 JSON Schema：必须包含 `title`、`body` 字符串，不允许其他字段；不设置 `minLength` 或 `maxLength`。
- 应用校验：标题、正文都是字符串，去除首尾空白后均非空；不检查标题或正文的字符数量。
- CLI 附加指令不再规定固定字数，长度要求由 `prompts/copy.md` 决定。修改提示词即可改变长度要求，原提示词中的要求不会被自动修改。

界面上的字符数只是统计展示，不会触发拦截或重试。

## 没有做的程序化内容检查

程序不会判断图片中文是否正确、排版是否好看、内容是否真实、是否符合主题或覆盖所有要求；不会检查文案是否包含表情、是否出现价格、是否与图片完全一致。这些仍由提示词约束和人工审核负责。格式、数量非空和文件可解码也不代表模型完整遵守了提示词。
